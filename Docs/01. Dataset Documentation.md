The Wearable Biomechanics project dataset is managed via a central command interface bridging **Google Drive storage** and **Google Colab**. The system utilizes the [OpenDatasetStore](https://github.com/janithcyapa/OpenDatasetStore) utility to maintain an automated, JSON-indexed manifest of all experimental data.
## 1.  Storage Architecture
The dataset relies on a specific Google Drive shortcut configuration, automatically generating the following structural hierarchy
```
My Drive/
└── Datasets/
    └── Wearable-Biomechanics/
        ├── index/
        │   ├── entities_subjects.json
        │   └── entries_experiments.json
        ├── raw_data/
        │   └── experiments/
        └── related_files/
        │    └── experiments/
        └── processed_data/
            └── experiments/
```

- **`index/`**: Stores the JSON manifests for both registered subjects and recorded experiments.
- **`raw_data/`**: Houses the uploaded CSV files containing raw biomechanical time-series data.
- **`related_files/`**: Contain non-dataset files related to the experiment such as video recordings.
- **`processed_data/`**: Designated for clean, processed data saved as **Parquet** files.
## 2.  Entity Management: Subjects

Test subjects are registered as unique entities within the dataset. Each participant is assigned a unique identifier following the **`sub_{num:04d}`** format (e.g., `sub_0001`).

| **Field**       | **Type** | **Description**                                                           |
| --------------- | -------- | ------------------------------------------------------------------------- |
| **Entity ID**   | String   | Auto-generated unique identifier.                                         |
| **Name**        | String   | Full name of the participant.                                             |
| **Age**         | Number   | Participant's age.                                                        |
| **Weight**      | Number   | Participant's current weight in kilograms.                                |
| **Height**      | Number   | Participant's height.                                                     |
| **Experience**  | Integer  | Years of relevant experience.                                             |
| **Achievement** | String   | Notable prior achievements (e.g., "Intermediate bronze medal 2025").      |
| **Best Weight** | String   | Personal best weight metric.                                              |
| **Notes**       | String   | Additional contextual information, such as participation in other sports. |

## 3.  Entry Management: Experiments

Experimental trials are logged as entries linked to specific subjects. The system records multi-modal data encompassing raw IMU telemetry, video captures, and observational notes.

- **Entry ID Format:** `{type}_{num:04d}` (e.g., `experiments_0001`).
- **Raw Data Naming Convention:** `{entry_id}_{entity_id}_{ts}.csv`.
- **Processed Data Naming Convention:** `{entry_id}_{tag}.parquet`.

Each experiment record captures the following metadata:
- **Target Subject:** The unique `Entity ID` of the performing participant.
- **Activity Type:** A description of the physical movement, such as "Clean & Jerk".
- **Timestamp:** The exact date and time the experiment was recorded.
- **Weight Used:** The physical weight utilized during the activity, recorded in kilograms.
- **Notes:** Trial-specific observations, such as repetition counts or sensor detachment issues.
- **Related Files:** An attachment dictionary mapping additional media to the trial, restricted to predefined labels: `front_video`, `side_video`, `raw_zip`, or `other`.
## 4.  Access and Configuration Constraints

- **Storage Backend:** The system connects directly via a local Google Drive mount in Colab.
- **Permissions:** Contributors must have at least "Editor" access to the shared `Wearable-Biomechanics` folder to upload data.
- **Pathing:** Users must place a shortcut to the shared folder exactly at `My Drive/Datasets/Wearable-Biomechanics` to ensure functional path resolution.
